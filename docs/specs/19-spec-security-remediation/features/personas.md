# Personas used in the feature files

Permissions are the live production role data recorded in `../prod-verification-2026-09-26.md`.
CHA-derived permissions come from `lib/security.ts` `CHA_ROLE_PERMISSIONS` and apply only while the
member is on a non-dropped roster row of a weekend whose group is ACTIVE.

| Persona (step text)              | How they are set up                                                                       | Effective permissions relevant to Epic 0                                                                                                                                                                              |
| -------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| an anonymous visitor             | No session. Holds only the public publishable (anon) key that ships in the browser bundle | None                                                                                                                                                                                                                  |
| a member with no roles           | Logged in. No `user_roles` rows, no roster placement                                      | Read everything logged-in members read; write only own rows                                                                                                                                                           |
| a team member                    | Member with a non-leadership CHA role (e.g. Table Leader) on the ACTIVE weekend roster    | Same as member, plus own team forms and own fee status                                                                                                                                                                |
| the Rector of the active weekend | `cha_role = 'Rector'` on the ACTIVE weekend; **no** `user_roles` rows                     | CHA-derived: `WRITE_TEAM_ROSTER`, `READ_TEAM_ROSTER_BUILDER`, `READ_WRITE_TEAM_PAYMENTS`, `READ_CANDIDATE_MEDICAL_INFO`, …                                                                                            |
| the Assistant Head Cha           | `cha_role = 'Assistant Head'` on the ACTIVE weekend; no `user_roles`                      | CHA-derived: `WRITE_TEAM_ROSTER`, `READ_WRITE_TEAM_PAYMENTS`, …                                                                                                                                                       |
| a Pre-Weekend Couple member      | `Pre Weekend Couple` role                                                                 | `READ_CANDIDATES`, `WRITE_CANDIDATES`, `DELETE_CANDIDATES`, `WRITE_PAYMENTS`, `READ_CANDIDATE_MEDICAL_INFO`, other candidate reads                                                                                    |
| the Treasurer                    | `Treasurer` role                                                                          | `READ_PAYMENTS`, `READ_WRITE_TEAM_PAYMENTS`, `WRITE_PAYMENTS` (no `READ_ADMIN_PORTAL` in prod today; `supabase/seed.sql` also grants it locally)                                                                      |
| a Leaders Committee member       | `Leaders Committee` role                                                                  | `READ_ADMIN_PORTAL`, `WRITE_TEAM_ROSTER`, `READ_TEAM_ROSTER_BUILDER`, `WRITE_PAYMENTS`, `WRITE_EVENTS`, `WRITE_USER_ROLES`, `WRITE_WEEKENDS`, `WRITE_SETTINGS`, `WRITE_CANDIDATES`, `FILES_UPLOAD`, `FILES_DELETE`, … |
| an Admin                         | `Admin` role (no `FULL_ACCESS`)                                                           | `READ_ADMIN_PORTAL`, `READ_CANDIDATES`, `READ_WEEKENDS`, `WRITE_SETTINGS`, `FILES_UPLOAD`, `FILES_DELETE`, `READ_DROPPED_ROSTER`                                                                                      |
| the Full Access owner            | `Full Access` role                                                                        | `FULL_ACCESS` (satisfies every permission check; may impersonate)                                                                                                                                                     |
| a candidate                      | Not a user. Identified only by the UUID in their forms link and their fee link            | None                                                                                                                                                                                                                  |

"Signed in as X while impersonating Y" means the Full Access owner set the impersonation cookie for Y;
the app then acts as Y for permission checks while `auth.uid()` in the database stays X.
