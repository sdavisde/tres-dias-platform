## Proofs for the fixes

- **M1:** `yarn test lib/redirect.test.ts` → 6 tests pass, including the three bypass strings the audit
  used and two backslash variants.
- **H1 (app):** `services/identity/roles/inheritance.test.ts` → `roleGrantsFullAccess` /
  `inputGrantsFullAccess` cases pass.
- **H1 (DB), M3, L1 (psql, one transaction, rolled back, 0 probe rows left):**
  - As a user whose only role holds `WRITE_USER_ROLES`: adding `FULL_ACCESS` to their own role →
    RLS violation; creating a role with `FULL_ACCESS` → RLS violation; basing their role on the
    Full Access role → RLS violation; inserting themselves into the Full Access role → RLS
    violation; updating the Full Access role → `UPDATE 0`; creating an ordinary role → `INSERT 0 1`.
  - Same user inserting a candidate with `status = 'confirmed'` → RLS violation; with
    `status = 'sponsored'` → `INSERT 0 1`.
  - As the existing Full Access holder: adding `FULL_ACCESS` to the probe role → `UPDATE 1`;
    adding the editor to the Full Access role → `INSERT 0 1`.
  - `pg_proc.proacl` for every function in `public` lists only `postgres`, `authenticated`,
    `service_role` (and `supabase_auth_admin` for `sync_users`); no `=X` (PUBLIC) entry remains.

## Decisions needed from the owner

1. **C1 — open signup.** With `enable_confirmations = false` and signup on, anyone can create an
   account and then read every table members can read, including `candidate_info.medical_conditions`
   and `payment_transaction`. Options: (a) require an invite/join code before an account gets any
   read access (Epic 3's "zero privileges by default" made real today via a `community_members`
   check in the SELECT policies — effectively Epic 2's first migration), (b) turn on email
   confirmation and a join gate, (c) accept the exposure until Epic 2. The audit's view is that (a)
   or (b) must ship before any second tenant exists. This session's recommendation: (a), because it
   also is the tenancy boundary and does not add login friction for existing members.
2. **H2 — `files` bucket.** Flip to private and serve through signed URLs (`getFileDownloadUrlAction`
   already exists). Small change; the only UI dependency is `FileBrowserTable.tsx` using
   `getPublicUrl`.
3. **M6 — own-row column restriction.** Keep own-email edits (current default) or restrict the
   `users` own-row UPDATE to profile columns via a trigger. Must be decided before `community_id`
   lands on `users` or `weekend_group_members`.
4. **M2** follows from C1: once non-members cannot read `candidates`, the forms UUID is again only
   in the emailed link.

## Readiness after the fix-ups

All findings the owner's decisions allow are fixed and proven. The gate for Epic 2 is **conditional
on the owner's answer to C1 and H2**: with (a)/(b) for C1 and a private `files` bucket, the audit's
blocking list is closed; M4/L1-style scoping is carried into Epic 2 as designed.
