### Notes

- Tests are co-located as `.test.ts` beside the source (no `__tests__` dirs); run with `yarn test` (Jest 30 + ts-jest, `testMatch: **/*.test.ts`, so `.tsx` is not matched). Repo pattern: pure helpers get unit tests; UI is verified by the manual checklist.
- Lint with `yarn lint` (never raw `npx eslint`); type-check with `npx tsc --noEmit`; `yarn build` is the gate for Unit 3 because pulling a `server-only` module into a client graph fails the build.
- Server actions return `Result<Error, T>`; use `Results.*` helpers and `isNil()`; user-facing errors go through `toastError()`. UI is shadcn-only.
- Commits are Conventional Commits; header and body lines ≤ 100 chars (commitlint). Never put the literal skip-ci marker in a commit body.
- **The owner runs the local database and dev server.** Never run `yarn db:reset`, `yarn db:start/stop` or `yarn dev` yourself; ask, and describe what to run. Migrations are applied by the owner locally and by CI on merge to `main` (`supabase db push` then `supabase config push`).
- Migrations are the source of truth. Every migration in this spec starts with a header comment listing each policy it drops and recreates (FR-1.9). Regenerate `database.types.ts` with `yarn db:generate` after schema changes (Units 5 and 6).
- `supabase config push` runs on every merge to `main` and overwrites prod auth settings, so `config.toml` is the only place to change `[auth]` keys.
- Policies written `TO authenticated, anon` cannot be edited per role: drop and recreate. Baseline line numbers below refer to `supabase/migrations/20260118030550_remote_schema.sql` (abbreviated `RS`).
- Impersonation keeps `auth.uid()` as the admin's id. Every ownership clause in RLS needs `OR hp('FULL_ACCESS')`; every app-level ownership predicate acts as the impersonated user.
- React `cache()` does not memoize outside a render, so actions that now call `getLoggedInUser()` internally pay one auth lookup per invocation. Acceptable for click-driven mutations.
